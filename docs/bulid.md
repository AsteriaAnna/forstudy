# PHM2010 刀具磨损预测项目开发规范文档
## 前置基础统一约定
1. **统一 ID 规则**
- 刀具 ID：固定`c1/c4/c6`
- 切削唯一标识：组合 ID `{tool_id}_{cut_num}`，全流程全程固定不变
- 运行版本 ID：单次流水线分配唯一 run 编号，输出目录隔离归档

2. **信号基础规格**
- 固定 7 通道：force_x、force_y、force_z、vib_x、vib_y、vib_z、ae
- 单条切削信号标准形状：`(采样点数, 7)`

3. **架构约束**
- Stage1/2/3 串行绑定执行，不可拆分独立调试
- Stage4/5/6 依赖上游落地数据文件，支持单独运行调试

4. **全局监测与日志规范**
- 日志等级：INFO 正常流程、WARN 轻微异常、ERROR 严重异常、STAT 统计汇总
- 全局统计计数器：总加载数、合格有效数、过滤丢弃数、各类异常分项计数
- 切削状态标识：LOADED 已加载、VALID 校验合格、FILTERED 异常过滤、PROCESSED 处理完成、SKIPPED 跳过
- 异常统一归类：文件缺失、信号维度错误、空值全零、标签缺失、幅值超限、波形断点、特征非法等

5. **数据缓存与断点续跑机制**
- 流式处理阶段1-3：单条数据内存流转，处理完成后落地缓存，不长期占用批量数据
- 缓存区分临时缓存与永久产出，临时文件单次运行结束可按需清理，阶段结果文件保留复用
- 支持断点续跑，可读取历史合法缓存数据接续执行，无需全量重新加载解析原始文件
- 缓存覆盖规则：同版本运行默认增量更新，新版本运行独立生成目录，互不覆盖历史数据

6. **数据穿透与隔离规则**
- 全局穿透共享数据：刀具切削ID、运行版本标识、全局统计台账、日志监测实例、基础通道规格
- 阶段隔离数据：局部处理参数、临时运算变量、单阶段判定阈值，仅当前阶段内部生效
- 刚性约束：禁止跨阶段篡改原始信号结构、身份ID、磨损标签核心数据

7. **异常兜底与容错重试机制**
- 文件读取失败配置有限重试次数，重试无果标记异常并跳过当前样本
- 单条切削数据报错仅废弃本条样本，不终止整体流水线运行
- 区分临界异常与硬性错误，临界问题告警记录，严重问题直接拦截过滤
- 所有异常留存溯源信息，形成报错、记录、处置闭环

8. **模块解耦与调用约束**
- 流水线组Stage1-3必须整体调用，禁止单独调取内部单阶段执行
- 下游模块仅可读上游产出文件，无权修改前置阶段生成的数据
- 核心公共工具库仅提供调用接口，业务代码不可直接改写底层通用逻辑
- 阶段之间以磁盘文件完成数据交互，不采用代码直接耦合调用

## Stage1 逐切削流式原始数据加载
1. **阶段名称 & 编号**
Stage1 逐切削流式原始数据加载

2. **阶段定位**
项目数据入口，以单切削为单位流式读取传感器信号与磨损真值，完成数据解析、ID 绑定与信号标签初次对齐，同步记录运行状态日志与基础数据监测，为后续质检提供合规原始数据源

3. **前置依赖**
无，项目起始阶段

4. **输入数据契约**
- 来源：本地项目数据集根目录
- 信号文件：后缀 csv 格式，单文件存储单次切削 7 通道时序数据，无表头
- 标签文件：各刀具目录下`{tool_id}_wear.csv`，包含 cut 编号、三刃磨损量
- 数据形态：离散独立切削文件，无统一索引表

5. **核心功能细则**
- 遍历 c1/c4/c6 三类刀具目录，递归检索所有符合命名规则的切削信号文件
- 兼容多类文件名格式，解析映射得到标准切削序号
- 建立刀具 + 切削组合唯一 ID，绑定单条数据固定身份标识
- 低内存流式读取，单次仅加载单一切削完整信号，不批量常驻全部数据
- 批量读取对应刀具磨损表格，建立切削编号与磨损值映射关系
- 依据切削编号，完成单条信号与对应磨损标签一对一绑定对齐

6. **关键校验检查点 & 监测规则**
- 解析生成的组合 ID 无重复、无错乱编号
- 读取信号数组维度严格为`(N,7)`，通道数量不缺失不冗余
- 每条切削均可检索匹配到有效磨损数值，无悬空无标签数据
- 排除全空、全零、读取损坏的无效信号文件
- 实时监测统计：成功加载数、文件缺失数、信号损坏数、标签缺失数

7. **日志记录规范**
- 单条切削正常加载完成，输出 INFO 级别日志，记录切削唯一 ID
- 切削文件检索失败，输出 ERROR 级别日志，登记异常 ID 与缺失原因
- 信号读取异常损坏，输出 ERROR 级别日志，标记无效数据条目
- 切削无匹配磨损标签，输出 WARN 级别日志，备注数据缺陷
- 阶段收尾输出 STAT 汇总日志，统计总文件数量、成功加载数量、失败数量、异常类型分布

8. **输出数据契约**
单切削结构化数据单元，流式向下传递
- signal：np.ndarray，形状`(sample_len,7)`，原始未处理时序信号
- tool_id：字符串，刀具标识 c1/c4/c6
- cut_unique_id：字符串，组合唯一身份 ID
- wear_label：字典，存储 flute_1/flute_2/flute_3 三组磨损浮点值

9. **阶段产物清单**
- 数据加载统计日志：刀具切削总数、成功读取数、缺失文件记录
- 原始信号样本波形可视化图
- 文件异常、读取失败明细日志

## Stage2 多维度数据质量验证
1. **阶段名称 & 编号**
Stage2 多维度数据质量验证

2. **阶段定位**
对加载完成的原始切削数据执行 9 项标准化质量筛查，剔除异常脏数据，同步监测数据缺陷、记录校验日志，保障进入预处理环节的数据具备有效分析价值

3. **前置依赖**
必须完成 Stage1 原始数据加载，依赖对齐后的信号 + 标签单元数据

4. **输入数据契约**
- 输入载体：Stage1 输出的单切削结构化数据流
- 数据格式：原始 7 通道信号数组、绑定完整唯一 ID 与磨损标签
- 无额外外部文件输入

5. **核心功能细则**
- 执行预设 9 项逐通道质量检测：空值检测、信号断点检测、采样长度区间校验、通道幅值合理性校验、通道相关性异常判别
- 校验磨损标签数值区间，剔除超出工程合理范围的异常磨损值
- 二次复核信号与切削 ID、磨损标签绑定关系，杜绝错位匹配
- 分类统计异常类型，对不合格切削执行拦截过滤，不流入下一阶段
- 汇总全量切削质检结果，生成量化质量统计信息

6. **关键校验检查点 & 监测规则**
- 9 项通道质检全部合规，无超标异常信号
- 磨损数值处于行业合理取值区间，无离谱极值
- 数据绑定关系二次核验无误，不存在 ID 与标签错位
- 统计台账严格匹配：总加载数 = 合格数据数 + 异常拦截数
- 分项监测：空值异常、波形断点、幅值超限、标签异常、匹配错位各类缺陷数量

7. **日志记录规范**
- 切削全部质检项通过，输出 INFO 级别日志，留存合格 ID 信息
- 任意质检项判定不合格，输出 ERROR 级别日志，标注异常类型、异常通道与切削 ID
- ID 与标签匹配校验出错，单独登记错误日志，警示数据错位风险
- 阶段结束输出 STAT 质检汇总日志，统计合格占比、各类异常占比

8. **输出数据契约**
仅保留校验合格的结构化数据单元
- signal：np.ndarray，形状`(sample_len,7)`，原始合格信号
- tool_id、cut_unique_id、wear_label：继承上游有效标识与标签信息

9. **阶段产物清单**
- 全维度数据质量检验报告
- 异常切削分类记录表，标注异常原因
- 合格数据统计汇总表

## Stage3 信号清洗与标准化预处理
1. **阶段名称 & 编号**
Stage3 信号清洗与标准化预处理

2. **阶段定位**
对质检合格的原始信号做降噪滤波、畸变修正与幅值归一化处理，统一数据分布尺度，全程监测信号形变与数值变化，记录处理运行日志，生成规范可用的干净信号数据集

3. **前置依赖**
必须完成 Stage2 质量验证，仅使用校验通过的合格切削数据

4. **输入数据契约**
- 输入载体：Stage2 筛选后的合格单切削数据流
- 数据格式：未做加工的 7 通道原始有效信号、配套身份 ID 与磨损标签

5. **核心功能细则**
- 选用适配切削信号的滤波算法，去除环境噪声、高频干扰分量
- 修正信号趋势偏移、突变异常峰值，还原真实切削工况波形
- 按通道维度执行标准化 / 归一化运算，统一各通道数据量纲与分布范围
- 维持原有通道排布顺序与数据采样长度，不篡改信号基础结构
- 保留身份 ID、磨损标签与预处理后信号的绑定关系

6. **关键校验检查点 & 监测规则**
- 处理后波形无失真、无畸形截断，符合切削信号物理特征
- 标准化后各通道数值分布满足预设尺度范围
- 数据维度`(sample_len,7)`与输入完全一致，结构无改动
- 身份标识、磨损标签绑定关系全程未丢失错乱
- 监测指标：处理前后信号均值方差、滤波异常点数、标准化数值区间合规率

7. **日志记录规范**
- 单条切削预处理顺利完成，输出 INFO 级别日志，记录处理耗时与基础参数
- 信号处理出现畸变、数值溢出等故障，输出 ERROR 级别日志并跳过当前样本
- 各通道标准化缩放参数统一归档写入日志
- 阶段收尾输出 STAT 汇总日志，统计总处理数量、处理成功率、通道数值整体分布

8. **输出数据契约**
预处理完成的标准干净数据单元，落地存储供后续阶段调用
- processed_signal：np.ndarray，形状`(sample_len,7)`，降噪标准化后信号
- cut_unique_id、tool_id、wear_label：完整继承绑定信息

9. **阶段产物清单**
- 预处理前后波形对比可视化图
- 数据标准化参数统计文件
- 预处理流程执行日志

## Stage4 多域特征提取
1. **阶段名称 & 编号**
Stage4 时域频域时频域多域特征提取

2. **阶段定位**
基于预处理干净信号，挖掘多层次表征特征，将时序信号转化为模型可学习的特征向量，监测特征合法性与维度统一性，记录提取运行日志，搭建数据集特征基础

3. **前置依赖**
必须完成 Stage3 预处理，读取落地存储的标准化干净信号数据

4. **输入数据契约**
- 来源：Stage3 输出的本地存储数据文件
- 格式：7 通道规整时序数组、附带唯一切削 ID 与磨损标签

5. **核心功能细则**
- 批量计算时域统计特征：均值、方差、均方根、峰峰值、峭度等
- 基于傅里叶变换求解频域特征：频谱幅值、频率重心、谱熵等
- 采用小波 / 短时傅里叶变换提取时频联合域特征
- 拼接三类维度特征，组成单切削高维特征向量
- 建立特征向量与切削 ID、磨损标签的对应索引

6. **关键校验检查点 & 监测规则**
- 单样本特征维度固定统一，无维度缺失、维度错乱
- 特征数值无无效 NaN、无穷大异常值
- 特征与原始切削样本、磨损标签索引匹配无误
- 监测统计：有效特征样本数、非法异常特征数量、维度偏差样本数

7. **日志记录规范**
- 样本特征正常提取完毕，输出 INFO 级别日志，记录样本唯一标识
- 出现空值、无穷值等非法特征，输出 ERROR 级别日志并标记异常样本
- 阶段结束输出 STAT 日志，汇总特征维度规格、有效样本总量

8. **输出数据契约**
- feature_vector：np.ndarray，固定维度特征向量
- 索引映射表：特征向量关联 cut_unique_id、磨损标签

9. **阶段产物清单**
- 特征数值统计表
- 特征分布、特征相关性可视化图表
- 特征 - 样本索引映射文件

## Stage5 数据增强与样本重构
1. **阶段名称 & 编号**
Stage5 数据增强与训练样本重构

2. **阶段定位**
扩充样本数量、均衡样本分布，通过变换算法生成新增样本，监测样本合理性与类别均衡度，记录增强重构日志，按照模型输入格式重构样本结构，提升数据多样性

3. **前置依赖**
必须完成 Stage4 特征提取，依托成型特征数据集开展加工

4. **输入数据契约**
- 来源：Stage4 输出的特征向量集、样本索引文件
- 数据形式：带标签的标准化高维特征样本

5. **核心功能细则**
- 采用高斯噪声叠加、幅值缩放、时序平移等方式做样本增强
- 滑动窗口切割方式拆分长时序样本，生成多组子样本
- 统计磨损标签分布，对稀缺样本做补充扩增，平衡类别占比
- 统一所有样本维度结构，规整模型输入格式

6. **关键校验检查点 & 监测规则**
- 增强样本物理特征合理，无违背切削规律的异常样本
- 所有重构样本维度规格统一
- 样本标签分配正确，类别分布趋于均衡
- 监测统计：原始样本总量、增强后样本总量、样本扩增倍率、各类标签占比偏差

7. **日志记录规范**
- 单组样本增强重构完成，输出 INFO 级别基础日志
- 生成违背物理规律的异常样本，输出 WARN 日志并剔除无效样本
- 阶段收尾输出 STAT 汇总日志，对比增强前后样本规模、类别分布变化

8. **输出数据契约**
扩增均衡后的完整样本集
- 规范维度样本特征数组
- 一一对应的磨损标签序列
- 样本来源溯源索引

9. **阶段产物清单**
- 增强前后样本数量对比报告
- 样本分布均衡性图表
- 重构完成的标准样本数据集

## Stage6 数据集划分与 TFRecord 构建
1. **阶段名称 & 编号**
Stage6 数据集划分与 TFRecord 格式构建

2. **阶段定位**
划分训练、测试子集，规避数据泄露风险，封装为深度学习通用 TFRecord 格式，监测数据集完整性与可用性，记录构建归档日志，生成可直接投入模型训练的最终数据集，并留存版本归档信息

3. **前置依赖**
必须完成 Stage5 样本重构，使用增强均衡后的样本集

4. **输入数据契约**
- 来源：Stage5 输出的标准化样本与配套标签
- 数据格式：统一维度特征样本、对应磨损真值标签

5. **核心功能细则**
- 按预设比例、依据刀具 / 切削维度划分训练集、测试集，规避数据泄露
- 按照 TFRecord 协议结构，序列化封装样本特征与标签
- 生成数据集版本说明、划分规则、样本数量统计文档
- 归档固化最终数据集，关联运行版本信息

6. **关键校验检查点 & 监测规则**
- 训练 / 测试集无样本重复、无交叉泄露
- TFRecord 文件可正常读取解析，样本标签匹配完整
- 数据集整体规模、划分比例符合项目训练要求
- 监测统计：训练测试样本数量、重复样本排查数量、文件读写成功率

7. **日志记录规范**
- 数据集划分、序列化封装正常完成，输出 INFO 级别日志
- 存在样本重复、标签不匹配问题，输出 ERROR 级别日志并修正处理
- 归档完成后输出 STAT 日志，记录数据集版本、划分比例、整体样本规模

8. **输出数据契约**
- 训练集、测试集 TFRecord 序列化文件
- 数据集基础信息、划分规则、版本元数据

9. **阶段产物清单**
- 最终训练、测试数据集文件
- 数据集版本说明书
- 数据集划分统计报表

## 一、数据读写权限管控
1. 只读权限目录
`data/raw` 原始数据集仅允许读取，禁止新增、修改、删除任意源文件，保障数据源不可篡改。
2. 读写权限目录
`data/interim`、`results`、`data/processed` 可正常读写、生成、覆盖阶段产物。
3. 权限约束
公共工具代码仅封装调用逻辑，业务脚本无权改写底层工具源码；下游模块不可回写上游阶段数据。

## 二、项目版本与归档管理
1. 版本划分
- 代码版本：迭代留存开发版本，重大功能改动单独标记分支
- 运行数据版本：以run目录独立隔离，不同批次运行数据互不干扰
- 数据集版本：最终TFRecord附带元信息标注版本号、生成时间、数据规格

2. 归档规则
有效运行成果长期留存；调试临时文件可定期清理；正式交付版本完整打包归档，附带对应规范文档与统计报告。

## 三、上下游数据兼容约束
1. 格式兼容
下游读取文件必须匹配上游输出格式、数组维度、字段结构，格式变更需同步全文档同步修订。
2. 规格锁定
7通道排布顺序、ID格式、标签字段结构全程固定，不随意调整字段顺序与命名。
3. 废弃数据处理
拦截过滤、异常报错的样本统一标记归档，不混入正常数据集，便于问题回溯复盘。

## 四、上线交付验收标准
1. 流程验收
1-3流水线可完整串行执行，4-6模块可独立调用，全链路无卡死、无批量数据错乱。
2. 文件验收
各阶段产物、日志、图表、报告齐全，命名路径完全符合规范。
3. 数据验收
最终数据集可正常读取解析，特征、标签匹配无误，满足模型训练输入要求。
4. 文档验收
规范文档与实际代码、数据结构完全一致，可作为开发、调试、交付依据。

## 五、安全与冗余规避规则
1. 重复校验
生成文件前检测同名文件，按需选择覆盖或跳过，避免无效重复生成。
2. 内存冗余控制
流式处理严格恪守单样本加载规则，杜绝一次性加载全量大数据引发内存溢出。
3. 路径容错
文件读写适配相对路径，避免固定本地绝对路径导致项目迁移后失效。
